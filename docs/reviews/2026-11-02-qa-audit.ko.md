## 3. 확인했고 올바랐던 것

감사 자체의 목록을 줄인 것입니다. 모든 comparer 가 적대적 쌍 90개를 참조 알고리즘과 같게 정렬했습니다.
범위 합집합 평가, 가장 높은 해제 fix, D154 동률 순서, D30 열거 목록 fallback 이 모든 정상 꼴에서
동작했습니다. D16 과 D15 는 수집 시점에 지켜지고, Red Hat 과 SUSE fix state 는 결정대로 매핑되며,
D129/D135 우선순위는 두 CSAF provider 에서 지켜지고, 모든 provider 가 범위를 `{Introduced: "0"}` 으로
열며, D159 변경은 실제 문서 53건에서 실제 rpm 바이너리만 이름 붙였습니다. exit 우선순위, 스트림 규율
(탐침한 모든 exit 2 경로에서 stdout 0바이트), compatibility 페이지 대 스키마 16, SARIF 규칙 선언(규칙
41개, 사용 41개), 에어갭 경로(레지스트리 분기만 네트워크 클라이언트를 import)가 모두 지켜졌습니다.
서명 체인은 무엇을 쓰거나 파싱하기 전에 검증하고, v0.14.0 릴리스는 발행 전에 toolchain 하한과 vulncheck
훅 여섯 번을 돌렸으며, `install.sh` 는 이 머신에서 실제 릴리스를 검증했습니다. 조작된 tar, rpm
데이터베이스, 버전, purl 로 닿을 수 있는 panic 은 없었습니다.

## 4. 후속, 여기서 하지 않은 것

- **#235 머지 뒤 첫 nightly 를 지켜볼 것**: 발행된 아티팩트의 Hummingbird nginx·tomcat 레코드는 다시
  빌드될 때까지 epoch 가 없다. `hummingbird` scandiff 대상의 grype 전용 튜플이 옛 레코드의 흔적이다.
- **`17 5 * * *` 의 첫 두 nightly** 를 DESIGN 이 약속한 05:20Z–13:00Z 창과 대조하고, 2026-11-09 의
  weekly 를 `23 20 * * 0` 에서 확인. 월요일 리뷰 루틴(저장소 밖)은 weekly cron 보다 최소 3시간 뒤여야
  한다. 01:30 UTC 는 괜찮다.
- **status 잡 세 개의 `timeout-minutes: 15`** 는 하는 일 기준으로 잡았다. 첫 느린 러너가 여유가
  필요한지 말해 줄 것이다.
- **월요일 루틴의 프롬프트** 는 아직 표의 모양에서 bridge 성장을 추론한다. 이제 `A_BRIDGED` 를 직접
  읽을 수 있다(#225).
- **SBOM 입력의 D153 4단계**: SRPM 의 다른 패키지 없이 mod_ssl 만 적은 SBOM 은 바이너리의 epoch 를
  유지하며, 잔여로 고정했다. 문서가 epoch 를 적지 않으면 "없음" 을 택하는 것은 D153 개정이다.
- **D134 소스 치환의 skip 경로 문구** 는 hit 경로의 주석을 일부만 따른다. 가독성 후속, 기존 문제.
- **세 provider 재시도 헬퍼의 Windows `ECONNRESET` 절** 은 Windows 의 실제 reset 에 절대 맞지
  않는다(Go 의 합성 errno 대 WSAECONNRESET). 구조상 Linux 전용이며 nightly 는 Linux 에서 돈다.
